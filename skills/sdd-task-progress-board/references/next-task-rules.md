# next task 決定ルール

## 1. 前提不足時

- `spec` または `plan` が `fail` の場合、未達チェックを埋める最小タスクを最優先にする。
- 最優先は「1回の編集で完了条件を満たせる」粒度にする。

## 2. 前提充足時

- 候補は `todo` と `in-progress` から選ぶ。
- 依存未解決タスクは候補から除外する。
- 優先順:
  1. `in-progress` で完了条件まで最短のタスク
  2. 依存解決済み `todo` のうち番号が最小のタスク
  3. テスト未実施の検証タスク

## 3. 出力形式

- 最優先1件は以下を必須にする。
  - タスクID
  - 実施内容
  - 依存
  - 完了条件
- 候補タスクは最大3件にする。
