# 成果物探索ルール

## 1. 探索対象

- 変更要求成果物（`CRQ-*`、change-request）
- `spec` 成果物（要件定義ドキュメント）
- `plan` 成果物（設計ドキュメント）
- `task` 成果物（タスク分解ドキュメント）
- `imple` 成果物（実装ログ/テスト結果）

## 2. 探索手順

1. プロジェクト内で `spec`, `plan`, `task`, `imple` を含むファイル名を検索する。
2. 明示的な成果物がない場合は、要件/設計/タスク/実装記録に該当する文書を代替候補として拾う。
3. 候補ファイルごとに「フェーズ判定可能な記述」の有無を確認する。

## 3. 判定に必要な最低情報

- spec: `REQ-*` または受け入れ基準の記述
- plan: `REQ-*` への対応設計、または設計方針
- task: `TSK-*` または完了条件付きタスク一覧
- imple: 変更内容とテスト結果の記述

## 4. 欠落時の扱い

- 必要情報が足りない場合は「欠落」と明記し、補完タスクを次タスク候補に入れる。
