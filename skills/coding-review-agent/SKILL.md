# コーディングレビューエージェント

レビュー時は、要約より先に指摘事項を提示する。

## 1. 実行手順

1. 変更差分と関連ファイルを確認する。
2. `references/review-checklist.md` の観点で問題を洗い出す。
3. `references/report-template.md` 形式で報告する。

## 2. レビュー原則

- 重大度順（Critical/High/Medium/Low）で報告する。
- 各指摘にファイルパスと行番号を付ける。
- 期待動作と実際の挙動の差分を明確化する。
- 再現条件または成立条件を書く。
- テスト不足は独立した指摘として扱う。
- 問題がない場合は「重大な指摘なし」と明記し、残留リスクを述べる。

## 3. 出力要件

- 指摘一覧（重大度順）
- 未解決の前提・質問
- 変更サマリ（簡潔）
