# 次タスク決定ルール

## 1. 最優先タスクの決定

- 未処理の `CRQ-*` がある場合は、`sdd-change-request-integration` の受付/影響分析タスクを最優先にする。
- `spec/plan` の確認質問（Q-*, QP-*）が未回答なら、回答取得タスクを最優先にする。
- 現在フェーズの未達項目を1つ選び、最小作業で完了できるタスクに分解して最優先にする。
- 未確定事項がある場合は「確認質問タスク」を最優先にする。

## 2. 候補タスクの作り方

- 候補は最大3件まで。
- 次の形式で記述する:
`[ID] タスク内容 / 依存 / 完了条件`

## 3. フェーズ別テンプレート

- spec 未達:
  - `REQ-*` 採番
  - 受け入れ基準の明文化
  - 制約/リスク整理
- plan 未達:
  - `REQ-*` と設計対応表作成
  - 非採用案の理由記述
  - テスト戦略記述
- task 未達:
  - `TSK-*` 採番
  - 依存関係整理
  - テストタスク追加
- imple 未達:
  - タスク別実装ログ追記
  - テスト結果追記
  - トレーサビリティ表更新
