# 仕様駆動開発スキル

このスキルを使うときは、必ず `spec -> plan -> task -> imple` の順序で進行する。

## 1. 実行ポリシー

- 最初に既存成果物を確認し、未完了の最も早いフェーズから開始する。
- 後続フェーズへジャンプしない。
- フェーズ成果物が不足している場合、先に不足分を作成してから先へ進む。
- 各フェーズの完了判定は `references/phase-gates.md` を使って実施する。
- 全フェーズで要件トレーサビリティを維持する。
- 追加仕様（要件追加/変更/削除）が発生した場合は `sdd-change-request-integration` を先に適用し、差分同期後に本フローへ戻る。

## 2. 成果物の作成順序

1. `spec`: `references/spec-template.md`
2. `plan`: `references/plan-template.md`
3. `task`: `references/task-template.md`
4. `imple`: `references/imple-template.md`

成果物はプロジェクト内の適切な場所に保存し、回答内でファイルパスを明示する。

## 2.1 妥当性判定ルール

- 各フェーズ終了時に `references/phase-gates.md` のチェック項目を評価する。
- 必須項目が1つでも未達なら `gate_result: fail` とし、次フェーズへ進まない。
- 判定結果は「満たした根拠」を短く添えて報告する。
- 根拠が不足する場合は追加作業を行い、再判定してから進む。

## 2.2 意思決定支援ルール

- `spec` と `plan` では、決定が必要な論点を最低3件は抽出する。
- 各論点に対して「推奨案」と「代替案」を提示する。
- 推奨案の理由は、コスト・リスク・運用性の観点で簡潔に示す。
- 未確定論点は確認質問として明示し、回答待ちのまま後続フェーズへ進まない。

## 3. フェーズ運用

### spec

- 問題定義、目標/非目標、ユースケース、受け入れ基準、制約、リスクを定義する。
- 要件IDを `REQ-001` 形式で採番する。
- 曖昧な要件を残さない。未確定事項は明示して質問する。
- 論点ごとの提案（推奨案/代替案）を提示し、意思決定を促す。

### plan

- `spec` を入力として、実装方式を設計する。
- 代替案と採用理由、影響範囲、テスト方針、移行方針を定義する。
- 設計項目に `PLN-001` 形式でIDを付け、対応する `REQ-*` を紐付ける。
- 実装判断の分岐点（技術選定、移行方法、検証戦略）を質問付きで確認する。

### task

- `plan` を実行可能な最小タスクへ分割する。
- タスクIDを `TSK-001` 形式で採番する。
- 各タスクに「入力」「実施内容」「完了条件」「依存関係」を必ず書く。
- 同時実行可能なタスクと順序必須タスクを区別する。

### imple

- `task` の順序と依存関係を守って実装する。
- 実装時に `TSK-*` と変更ファイル/テスト結果を対応付ける。
- 差分、テスト結果、未完了項目を記録する。
- 実装中に要件変更が発生したら `spec` に戻って更新し、以降の成果物も同期する。

## 3.1 追加仕様の扱い

- 変更要求は `CRQ-*` で管理する。
- 追加仕様は既存成果物へ上書きせず、差分として反映する。
- 差分反映時は `REQ-* -> PLN-* -> TSK-*` のトレースを崩さない。
- 差分反映後に必ずフェーズゲートを再判定する。

## 4. 出力フォーマット

各フェーズ終了時に次を報告する。

- `current_phase`
- `artifacts` (作成/更新したファイルパス)
- `gate_result` (`pass` / `fail` と理由)
- `next_phase`
- `open_questions` (あれば)

推奨の日本語ラベル:

- `current_phase`: 現在フェーズ
- `artifacts`: 成果物
- `gate_result`: 判定結果
- `next_phase`: 次フェーズ
- `open_questions`: 未解決事項

## 5. 完了条件

- `spec`, `plan`, `task`, `imple` の4成果物が揃っている。
- 各成果物が `references/phase-gates.md` の完了条件を満たしている。
- `REQ-* -> PLN-* -> TSK-* -> 実装/テスト` のトレースが確認できる。
